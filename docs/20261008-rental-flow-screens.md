# 대여 진행 단계별 화면 · 2026-10-08

## 변경 내용

- 기존 `QR`의 "대여 시작 / 반납 완료" 탭을 없애고 `RENTAL_FLOW`의 7개 단계로 분리했습니다. 제목·설명·진행 표시는 단계와 대여자/차용자 역할에 맞춰 바뀝니다.
- 예약 카드, 계약 화면, 앱 내 알림에서 들어올 때 계약의 서버 상태와 대여 전 사진 장수로 첫 단계를 정합니다. 사진과 계약 상태가 허용하지 않는 단계는 열 수 없습니다.
- QR 스캔 성공 시 결과 화면으로 이동합니다. 상대방이 QR을 보여주는 동안에는 4초마다 예약/계약 상태를 읽어 시작 또는 반납 결과 화면으로 자동 이동합니다. 화면을 떠나거나 앱이 백그라운드로 가면 갱신을 멈춥니다.
- 대여자의 대여 시작/대여 중 화면은 서버 결제 상태가 `paid`인 경우에만 "보증금 확보 완료"를 표시합니다. 상태를 읽지 못하면 확인 중과 새로고침을 표시합니다. 이 표시는 대여자 계좌 입금이나 별도 에스크로를 뜻하지 않습니다.
- 대여자는 반납 후 사진 1장 이상과 구성품/파손 체크리스트를 완료해야 반납 QR 화면으로 진행할 수 있습니다. 체크 상태는 현재 앱 실행 중 화면 상태이며 DB에 저장되지 않습니다. 문제 신고는 기존 분쟁 화면을 사용합니다.
- 팀원이 추가한 카메라 촬영·갤러리 선택·업로드 재시도·실제 상태 사진 미리보기를 각 사진 단계에 연결했습니다. 후기 화면의 선택형 별점 기능도 함께 유지합니다.
- 반납 QR 성공은 **반납 완료**이며 **환급 완료가 아닙니다**. 대여자는 기존 서버가 환급을 허용한 경우에만 환급 승인 버튼을 사용할 수 있고, 차용자는 환급 상태를 확인합니다.
- 서버 없는 시연 거래는 각 사진 단계에서 기존처럼 사진 5장을 채우고 별도의 "QR 인증 시연" 버튼으로 단계만 진행합니다. 실제 서버 거래의 QR 발급·검증 함수 및 결제·환급 API는 변경하지 않았습니다.

## 단계 전환

```text
SIGNED/READY ── 대여 전 사진 1장 이상 ──> HANDOVER_QR
     │ HANDOVER_PHOTOS                     │ 서버 QR 시작 확인
     └─────────────────────────────────────> STARTED ── 확인 ──> RENTING
                                                               │ 반납 진행
                                                               v
                             RETURNED <── 서버 QR 반납 확인 ── RETURN_QR
                                │                           ↑
                                │ 환급/문제 신고             │ 반납 후 사진 1장 이상
                                v                           │ 대여자 체크리스트
                            FEEDBACK <──────────────── RETURN_INSPECT
```

재진입 시 `SIGNED/READY`는 대여 전 사진 여부에 따라 `HANDOVER_PHOTOS` 또는 `HANDOVER_QR`, `RENTING`은 `RENTING`, `COMPLETED`는 `RETURNED`에서 시작합니다. `DISPUTED`는 기존 `FEEDBACK`으로 이동합니다. `STARTED`는 QR 상태가 바뀐 순간의 결과 화면이며 재진입 기본 화면이 아닙니다. 뒤로 가기는 `HANDOVER_QR → HANDOVER_PHOTOS`, `RETURN_QR → RETURN_INSPECT → RENTING`, `STARTED → RENTING`이고 나머지는 예약 목록입니다.

## 실기기 수동 확인 시나리오 (미검증)

테스트 계정 2개와 실제 결제가 승인된 예약 1건으로 진행합니다. APK 두 대의 서버 주소가 같은지 먼저 확인합니다.

1. 대여자와 차용자가 각각 대여 전 사진을 등록하고 QR 화면에 진입합니다. 한쪽이 QR을 보여주고 상대가 스캔한 뒤 **양쪽 모두** `STARTED`에 자동 이동하는지 확인합니다.
2. 대여자 화면의 보증금 확보 금액·대여료·기간·D-day가 서버 결제 상태와 일치하는지 확인합니다. 결제 상태 조회가 실패할 때는 "결제 상태 확인 중"이고 확보 완료로 보이지 않아야 합니다.
3. `RENTING → RETURN_INSPECT`로 이동합니다. 사진이 없거나 대여자 체크리스트가 미완료면 다음 버튼이 비활성화되는지 확인합니다. 반납 QR을 인증하면 양쪽 모두 `RETURNED`로 이동해야 합니다.
4. 반납 완료 직후 환급 상태가 "환급 대기"인지 확인합니다. 대여자가 "이상 없음, 보증금 환급 승인"을 누른 뒤 새로고침으로 환급 상태를 확인합니다. 별도 거래에서 "문제 신고"가 분쟁 화면으로 이동하는지 확인합니다.
5. 각 단계의 뒤로 가기를 확인하고, 앱을 재시작하거나 알림을 눌러 다시 들어왔을 때 서버 상태에 맞는 단계가 열리는지 확인합니다.

## 검증과 한계

`RentalFlowRulesTest`는 상태별 진입, 사진/서버 상태에 따른 앞 단계 차단, 뒤로 가기를 검증합니다. Android 빌드·JVM 테스트·Lint는 JDK 17에서 실행합니다. Windows의 한글 프로젝트 경로로 인해 JVM 테스트 클래스 로딩이 실패하는 환경에서는 같은 프로젝트를 가리키는 영문 임시 junction에서 실행합니다.

2026-10-09 팀원 변경 병합본 검증: 영문 임시 junction에서 `testDebugUnitTest assembleDebug lintDebug` 성공. JVM 테스트 32개 통과·실패 0개, Lint 오류 0개·경고 40개입니다. APK는 `ShareGuardAndroid/app/build/outputs/apk/debug/app-debug.apk`에 생성됐습니다. 초기 한글 경로의 테스트 실패는 클래스 로딩 문제였으며, 같은 코드의 영문 경로 재실행에서 전부 통과했습니다.

- 실제 두 기기의 QR 교환·결제 상태·환급은 아직 수동 검증이 필요합니다.
- 앱이 백그라운드이거나 화면을 벗어나면 자동 이동하지 않습니다. 다시 열면 서버 상태를 읽어 해당 단계로 들어갑니다. QR 화면의 자동 이동은 조회 간격과 네트워크에 따라 약 4초 이상 지연될 수 있습니다.
- 검수 체크리스트는 서버에 저장되지 않아 앱 재시작 시 다시 체크해야 합니다. 서버의 사진·QR 필수 조건은 그대로 유지되며 체크리스트는 UI 안내입니다.
- 보증금 확보 카드는 서버 결제 상태의 표시일 뿐 실제 결제 보관 방식이나 환급 권한을 변경하지 않습니다.
